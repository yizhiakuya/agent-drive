# 🔬 Agent Drive 完善度评审汇总（4 子代理 × 网络案例对比）

> 审查范围：Agent 循环/提示工程、记忆系统、工具设计与安全、产品体验
> 案例对比：Anthropic（Building Effective Agents / Claude Code 拆解）、OpenClaw、Mem0、Letta、Zep、OWASP LLM 安全、Codex UX
> 结论：**架构方向正确（业界最佳实践基本都做对了），但存在 9 个 🔴 正确性/安全 bug + 大量体验断点——"骨架优秀、血肉待补"**

## 🔴 必须立即修复（正确性 & 安全）

| # | 类别 | 问题 | 后果 |
|---|------|------|------|
| 1 | 路由 | "你好，帮我整理文件"等问候+任务句被吞 | 任务静默失败、能力归零 |
| 2 | 压缩 | 轮内压缩切出孤儿 tool 消息 | API 400 报错（必现） |
| 3 | 记忆 | MEMORY.md 从头部截断，新记忆在尾部 | 最新记忆永不注入 |
| 4 | 记忆 | set() 重建 USER.md 销毁用户手写内容 | 用户编辑丢失 |
| 5 | 压缩 | 滚动摘要 system 消息被 build_history 过滤 | LLM 摘要白生成、早期上下文永久丢失 |
| 6 | 安全 | 确认机制可伪造 + 确认后整轮重放 | 双重执行副作用（双写/双记） |
| 7 | 安全 | 审计日志明文记录 API key | 密钥泄露 |
| 8 | 安全 | 零 prompt injection 防护 | 恶意文件可操纵 Agent（自动写/持久化注入） |
| 9 | 体验 | 步数耗尽静默失败（空气泡） | 用户不知道任务失败 |

## 🟡 重要改进（可靠性 & 体验）

- set_llm_provider 升 red（数据外泄通道）；move/copy 静默覆盖需确认
- 最终回复双 LLM 调用（成本×2）；系统提示 LLM 状态恒"未配置"
- 确认恢复非确定性重放；Dreaming 漏日子不补；蒸馏无去重
- 检索无语义（纯子串）；无遗忘/矛盾处理；每日笔记保真度低
- 文件面板不刷新；生成不可停止；会话切换串消息；无预览/下载；零移动端

## ✅ 四大优点（业界对标不落下风）

1. 编排引擎：_execute 统一生成器 + 单一职责拆分
2. 提示工程：API 文档级工具手册 + 10 条行为准则
3. Actor-Critic 落地：6 个写操作 Critic 验证（业界少见）
4. 记忆分层：OpenClaw 式四层 + 记忆即文件（方向完全正确）

## 修复路线图

- **P0（今天）**：9 个 🔴 全修（先修正确性 1/2/3/4/5，再修安全 6/7/8）
- **P1**：🟡 安全类（set_llm_provider 升红、覆盖确认、注入防护）+ 成本（单次调用）
- **P2**：体验类（文件面板联动、停止按钮、串消息修复、预览/下载）
- **P3**：记忆增强（语义检索、遗忘机制、Dreaming 补跑）+ 移动端
