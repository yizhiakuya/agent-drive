# Agent Drive 产品与业务说明

> 文档用途：作为 Gemini 重新生成产品 UI/UX 前的业务上下文。
>
> 更新时间：2026-08-20 ｜ 文档性质：产品说明，不是视觉规范或页面实现方案。

本文只说明 Agent Drive 是什么、服务谁、解决什么问题、有哪些功能、业务如何运行以及产品边界。本文不规定页面布局、颜色、组件、动效或具体交互方案；这些部分由 Gemini 基于业务目标自行设计。

当前生产事实可交叉参考 [`product.md`](product.md)、[`architecture.md`](architecture.md) 和 [`security.md`](security.md)。

## 1. 产品是什么

Agent Drive 是一个面向个人用户的 Agent-first 私人网盘。

它不是简单的“文件存储 + 一个聊天窗口”，而是一个能够理解个人文件、协助用户完成文件工作的智能工作空间：

- 用户可以像使用普通网盘一样直接管理文件；
- 用户可以用自然语言让 Agent 查找、阅读、分析、整理和维护文件；
- 系统可以异步执行文件抽取、全文索引、向量索引、图片理解和自动化任务；
- 手机可以作为文件采集端，将相册内容安全同步到个人网盘。

### 一句话定义

**Agent Drive 是一个让个人文件可被存储、找到、理解并安全执行操作的智能文件工作空间。**

### 产品形态

- Web/PWA：主要工作入口，负责对话、文件管理、搜索、配置和任务查看；
- Android App：负责扫码连接、设备认证、后台相册同步、通知和移动端设备能力；
- Agent：负责理解用户目标、调用受限能力、反馈过程和结果；
- 后台任务系统：负责把耗时工作从用户请求中分离出来，保证索引和自动化可持续执行。

### 当前产品模型

- 面向个人单用户使用；
- 文件、会话、设备、任务和偏好都属于当前用户；
- 实际文件属于用户自己的文件空间；
- 模型是协助者，不是文件所有者；
- 所有涉及用户文件的动作都必须能够解释结果和影响。

## 2. 产品要解决的问题

### 2.1 文件越来越多，但越来越难找到

个人文件同时来自手机、聊天、下载、工作和生活记录。文件名、目录和创建时间无法完整表达内容，用户经常记得“文件讲了什么”，却不记得“文件叫什么、放在哪里”。

Agent Drive 通过名称搜索、全文抽取和语义搜索，让用户可以按照文件内容寻找资料。

### 2.2 文件整理需要大量重复劳动

用户经常需要判断文件主题、创建目录、移动文件、重命名和清理重复内容。这些动作规则明确但过程繁琐，适合交给 Agent 处理。

Agent Drive 允许用户描述目标，例如“整理资料目录下的合同和预算文件”，Agent 负责观察、规划、执行和汇报，用户保留最终控制权。

### 2.3 AI 能做事，但用户不容易信任它

如果 Agent 只返回一句“已完成”，用户无法知道它看了什么、改了什么、是否真的成功，也无法在出错时恢复。

Agent Drive 的产品要求是：

- 对只读动作可以快速完成；
- 对删除、移动、覆盖等高风险动作明确确认；
- 对执行过程给出可理解的阶段和结果；
- 对后台任务保留状态、错误和重试入口；
- 对文件操作和索引操作分别报告，不能把“文件已保存”误报成“已完成索引”。

### 2.4 手机产生内容，但整理发生在另一处

照片和截图主要在手机产生，整理、搜索和理解通常在网页完成。用户需要一个不打断日常使用的同步方式，同时避免重复上传、断网丢进度和设备令牌泄露。

Android App 提供扫码连接和后台相册同步，服务端负责去重、断点续传、文件发布和后续索引。

## 3. 目标用户

### 3.1 个人资料管理者

拥有合同、账单、学习资料、项目文档和个人记录，希望一个空间能长期保存并且容易找回。

核心诉求：安全、稳定、可搜索、可恢复，不想维护复杂的目录规则。

### 3.2 手机内容采集者

每天通过手机产生照片、截图和扫描件，希望内容自动进入自己的文件空间，不需要手动挑选和重复上传。

核心诉求：同步可靠、进度清楚、失败可重试、重复文件不泛滥。

### 3.3 Agent 协作用户

愿意使用自然语言管理文件，但需要知道 Agent 做了什么，并且能够在必要时停止、确认或回退。

核心诉求：结果真实、过程可理解、写操作可控、失败能恢复。

## 4. 产品价值

### 对用户的直接价值

1. **找得到**：不只按文件名，也能按内容和语义找文件。
2. **看得懂**：Agent 可以读取文本、总结文件、解释图片内容和汇总资料。
3. **理得动**：用户可以用目标描述代替重复的文件整理动作。
4. **跟得上**：手机照片可以持续同步，索引和自动化任务在后台运行。
5. **信得过**：关键操作有确认、状态、审计信息和错误恢复路径。

### 产品差异

Agent Drive 的重点不是提供更大的存储空间，而是把文件存储、文件理解和文件行动连接起来。用户面对的是“我的资料和目标”，而不是一组孤立的技术功能。

## 5. 功能范围

### 5.1 账户和个人空间

- Web 通过密码登录；
- 登录后建立当前用户会话；
- Android 通过一次性扫码配对获得设备访问资格；
- 设备可以被查看、撤销和重新配对；
- 用户的会话、文件、任务、设备和偏好按当前用户隔离。

### 5.2 Agent 对话

Agent 可以帮助用户：

- 查看网盘结构和文件信息；
- 按名称、路径或内容查找文件；
- 阅读文本、Markdown、图片等可处理内容；
- 总结文件、提取重点和回答基于文件的问题；
- 创建目录、移动、复制、重命名和删除文件；
- 查询任务、索引、设备和系统状态；
- 创建或执行自动化规则；
- 根据用户表达维护偏好和工作记忆。

对话能力不是无限制的通用电脑控制。Agent 只能调用产品登记的能力，并且不能接触用户的 Cookie、Bearer、API key、任意 URL、任意请求头或源代码执行入口。

### 5.3 文件管理

文件模块提供：

- 目录和文件列表；
- 文件夹创建、进入和浏览；
- 文件上传和服务端 MD5 校验；
- 文件预览和受限全文查看；
- 文件移动、复制、重命名和删除；
- 回收站、恢复和清理；
- 文件 revision、全文和向量索引状态；
- 文件容量和空间使用情况。

文件操作的产品原则是“不丢数据”：覆盖、复制、移动、删除和恢复都需要明确结果；文件已经发布但后台索引失败时，必须分别显示两个结果。

### 5.4 文件搜索和内容理解

#### 名称/路径搜索

适合用户知道文件名、目录名或路径片段的情况。搜索范围可以覆盖当前目录及其子目录。

#### 语义搜索

适合用户只记得内容、不记得文件名的情况。系统根据查询内容生成向量，在有效的文件内容索引中寻找相关结果，并返回文件、相关度和内容摘要。Agent 需要据此回答原文时，会使用面向证据的检索入口返回多个 chunk 及有限相邻上下文，而不是把单个最佳文件结果当作完整答案依据。

语义搜索依赖 embedding 服务和有效索引：

- 未配置 embedding 时，产品要明确提示配置缺失；
- 索引处理中时，产品要显示等待或部分可用状态；
- 文件 revision、抽取版本或 embedding fingerprint 不匹配时，旧结果不能继续参与搜索；
- 搜索不可用时不能伪装成成功但返回空结果。

#### 图片理解

可选的视觉模型可以为图片生成一段综合描述，再进入文件语义索引。图片描述必须绑定当前文件 revision，避免旧图片结果覆盖新内容。

### 5.5 后台任务和自动化

后台任务把耗时工作从用户请求中分离出来，包括：

- 单文件抽取和索引；
- 批量 embedding；
- 图片视觉索引；
- 全量索引重建；
- 失效索引清理；
- 清空 owner 全部文本/视觉向量；
- 每日维护；
- 自动化规则执行。

任务系统是独立业务模块：它通过正常 API 暴露任务查询、取消、重试和终态能力，返回自身的 queued/running/terminal 状态。文件、索引、外部模型处理和自动化是否需要任务化由具体业务 API 的实现语义决定；长操作由业务域通过监控端口登记任务，Agent 只调用业务 API 并读取返回的 monitor 状态，不直接把任务 API 当作业务入口。`cleanup-index` 只清理已失效索引记录，不能被解释为清空向量；清空向量使用独立的索引资源 API。

任务应该有明确的生命周期：排队、运行、等待重试、取消中、完成、跳过、失败或已取消。

任务中心的业务价值不是展示技术日志，而是回答：

1. 当前是否有事情正在运行；
2. 是否有需要用户处理的问题；
3. 哪些文件已经处理完成；
4. 失败后能否重试或修改配置；
5. 系统显示的索引状态是否可信。

### 5.6 模型和服务配置

用户可以配置：

- 对话模型；
- 聊天页本轮使用的模型；
- embedding 服务；
- 图片视觉模型；
- 模型地址、协议、模型名和 API key；
- 模型连接测试和模型列表探测。

当前支持 OpenAI 兼容、OpenAI Responses 和 Anthropic 对话协议；embedding 当前使用 Jina；视觉模型使用 OpenAI 兼容接口。聊天页的模型选择只覆盖当前请求，Provider 地址、协议和 API key 仍由设置页保存的配置决定。

API key 只在服务端加密保存和掩码展示。用户更换服务地址或协议时，不能无条件把旧 key 发到新地址。

### 5.7 Android 相册同步

Android App 提供：

- 扫码连接个人服务器；
- 加密保存服务器地址、设备 ID、设备令牌和同步设置；
- 相册读取权限和同步配置；
- Wi-Fi 条件、同步周期和目标目录；
- 后台同步、手动重扫和通知；
- 上传进度、失败状态和设备活跃时间。

同步业务规则：

- 服务端去重预检只用于优化，真正上传仍由服务端复算 MD5；
- 同名文件采用 noclobber 规则，不静默覆盖已有文件；
- 断网、认证失败或服务端瞬时错误不会把未完成的内容标记为已同步；
- checkpoint 只推进到完整成功的时间段，失败内容下次继续；
- 通知权限被拒不等于相册权限失败。

## 6. 核心业务流程

### 6.1 首次使用

1. 用户打开 Web，设置或输入个人密码；
2. 登录进入个人文件空间；
3. 配置对话模型，使 Agent 可以回答问题；
4. 如需要内容搜索，再配置 embedding；
5. 如需要图片理解，再配置视觉模型；
6. 如需要手机同步，在 Web 生成一次性配对码并用 App 扫码；
7. 用户可以从查看文件、搜索内容或发起一次对话开始使用。

模型、聊天页本轮模型选择、embedding、视觉和手机同步是相互独立的能力。某一项未配置，不应阻塞其他已经可用的能力；聊天页模型选择失败时仍可使用默认模型。

### 6.2 通过 Agent 整理文件

1. 用户提出目标，例如“整理资料目录中的合同和预算文件”；
2. Agent 先了解当前文件和目录状态；
3. Agent 给出计划或直接执行低风险读取；
4. 涉及移动、重命名、覆盖或删除时，系统要求用户确认；
5. 执行结果写入文件空间，并触发后续索引任务；
6. Agent 汇报已完成动作、未完成动作、失败原因和可恢复步骤；
7. 用户可以进入文件或任务详情核验结果。

### 6.3 搜索并理解文件

1. 用户输入文件名、路径片段或内容描述；
2. 系统根据搜索类型执行名称搜索或语义检索；
3. 返回匹配文件、大小、更新时间、索引状态和内容摘要；
4. 用户查看文件内容或让 Agent 基于选中文件继续回答；
5. 如果结果来自旧 revision、索引不可用或 provider 失败，系统必须说明真实状态。

### 6.4 手机照片同步

1. 用户完成一次扫码配对；
2. App 获取图片读取权限并保存同步设置；
3. WorkManager 在符合条件时扫描 MediaStore；
4. 客户端执行只读去重预检；
5. 服务端流式接收并复算文件 MD5，原子发布文件；
6. 同步进度和失败状态反馈给 App；
7. 文件变更事件触发全文、embedding 或视觉索引任务。

### 6.5 处理后台失败

1. 任务进入失败或等待重试状态；
2. 系统区分永久错误和瞬时错误；
3. 用户可以看到失败对象、阶段、原因和影响范围；
4. 对可恢复错误提供重试，对配置错误提供进入设置的路径；
5. 重试遵守任务去重和最大尝试次数，不能不断创建重复任务；
6. 文件已经发布时，不因索引失败而伪报文件上传失败。

## 7. Agent 的产品规则

### 7.1 能力边界

Agent 是个人文件助理，不是拥有无限权限的系统管理员。它只能使用已登记的产品能力，并且必须在当前用户的权限范围内工作。

### 7.2 操作风险

- 只读操作：查看、搜索、读取、统计和状态查询，可以直接执行；
- 低风险写操作：根据实际 operation 评估，可在产品规则允许时直接执行；
- 高风险写操作：删除、覆盖、批量移动、批量改名等，在请求批准/帮我批准模式下先确认；完全访问模式表示用户已明确授权 Agent 直接执行。
- 外部服务调用：只能通过已配置的 provider 和受控请求，不把用户凭据交给模型。

### 7.3 结果可信度

- Agent 不能把计划说成已经执行；
- Agent 不能把文件成功发布说成索引已经完成；
- Agent 不能在 provider 未配置时声称已完成向量化；
- 工具返回的结构化结果优先于模型自行猜测；
- 失败必须保留真实原因，并给出下一步，而不是用泛化的“系统异常”。

### 7.4 记忆和偏好

用户偏好、会话摘要和每日记录服务于后续协作，但不能覆盖当前用户明确的新指令。敏感信息在会话、摘要和记忆落库前需要脱敏；用于确认重放的原始参数属于受保护数据，不进入普通展示。

## 8. 产品安全和信任要求

从用户角度，产品必须让以下事实成立：

- 用户只能看到和操作自己的文件、会话、设备和任务；
- 密码、Cookie、Bearer、设备令牌和 API key 不显示给模型或普通日志；
- 文件路径不能越出个人文件空间，也不能访问内部索引和 staging 区域；
- 删除优先进入可恢复的回收站，而不是直接不可逆丢失；
- 上传、覆盖、复制和移动不会因为并发请求产生半成品或错误覆盖；
- 退出登录会使当前 Web/设备凭据失效；
- 外部 provider 故障不会被伪装成用户输入错误。

详细安全实现见 [`security.md`](security.md)，本节只作为产品信任要求。

## 9. 产品边界和非目标

当前不属于 Agent Drive 产品契约的能力：

- S3 或其他对象存储后端；
- 多用户、团队空间、组织角色和租户管理；
- iOS 客户端；
- 音频、视频转写和媒体知识库；
- 端到端加密文件存储；
- 公共分享链接和复杂的外部协作权限；
- 让模型获得任意 URL、浏览器脚本、JavaScript 或服务器代码执行权限。

这些能力如果未来要做，需要单独进行产品定义、权限模型和风险评估，不能在重设计中通过页面假装已经存在。

## 10. 当前产品问题与优先级

以下是当前产品层面的待改进事项，供 Gemini 理解产品优先级，不是 UI 布局要求：

| 优先级 | 产品问题 | 影响 |
|--------|----------|------|
| P0 | 文件夹浏览和文件预览的业务语义需要统一 | 用户无法稳定判断“打开目录”和“查看文件”是否是同一动作 |
| P0 | 任务统计、索引状态和语义搜索结果的有效性口径需要统一 | 用户会怀疑搜索结果和任务状态哪个是真实的 |
| P1 | 自动化失败历史需要被区分、解释和治理 | 当前问题容易被大量历史失败记录淹没 |
| P1 | Agent 执行结果需要与文件、任务和变更结果形成可核验闭环 | 用户难以判断 Agent 是否真的完成了目标 |
| P1 | 模型、embedding、vision 配置的依赖关系需要更容易理解 | 用户可能误以为某个模型配置能自动提供所有能力 |
| P2 | 手机同步失败和断点续传需要更易理解 | 用户需要知道是权限、网络、认证还是服务端处理问题 |

## 11. 产品成功标准

重设计和后续功能迭代应以以下结果为判断标准：

### 用户结果

- 新用户能理解 Agent Drive 是个人文件工作空间，而不是普通聊天应用；
- 用户能通过自然语言或直接操作找到目标文件；
- 用户知道 Agent 做了什么、没有做什么以及为什么；
- 用户可以安全地确认、停止、重试或恢复操作；
- 用户能判断文件、索引、任务和同步的真实状态。

### 产品结果

- 对话、文件、搜索、任务和手机同步形成连续的业务闭环；
- 失败信息可行动，配置问题、权限问题和瞬时错误不会混为一谈；
- 可选能力未配置时，核心文件管理仍然可以使用；
- 所有产品能力都落在清晰的个人权限和数据边界内；
- 产品不依赖用户记忆内部技术名词才能完成主要任务。

1. 先理解产品定位、用户、核心任务和功能边界；
2. 根据这些业务目标自行决定信息架构、页面布局、视觉语言和交互方式；
3. 不要把本文件中的技术实现名词直接暴露成用户文案；
4. 不要新增文档中明确列出的非目标能力或虚构数据；
5. 必须保留高风险操作确认、任务状态可信度、文件 revision、异步处理和个人数据边界；
6. 任何 UI/UX 方案都要服务于“找到、理解、安全行动、可核验”这条产品主线。

当前实现和工程边界请继续参考：

- [`product.md`](product.md)：当前产品事实；
- [`frontend-architecture.md`](frontend-architecture.md)：前端能力和状态边界；
- [`architecture.md`](architecture.md)：系统和数据边界；
- [`security.md`](security.md)：认证、凭据和文件安全边界；
- [`android.md`](android.md)：手机连接和相册同步业务。
